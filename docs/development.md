# Development workflow

**Node.js 22.16+** and **pnpm 10** required.

```sh
pnpm install
pnpm test
pnpm typecheck
pnpm cartridge:build
pnpm cartridge:verify
pnpm dev
```

The Next.js app is initially a concept preview, not a playable emulator. Static export: `pnpm build` -> `apps/web/out`.

The `.slop` prototype is a canonical JSON envelope compressed with deterministic gzip. It is a **v0 experimental file format**: manifest, compiled ES module and validated inline assets. Its source scan is NOT a JS sandbox. The CLI never executes a cartridge. **Do not execute public cartridge code until issue #4 passes the browser isolation/security gate.**

Games can be built by humans or AI using the same SDK types. Only type-only imports from `@slopboy/sdk` are permitted; runtime dependencies are intentionally excluded. The validator enforces package bounds and known asset palettes but cannot prove arbitrary source is safe. Browser runtime enforcement will come in P1.

The pinned `pnpm-lock.yaml` was generated by the first successful GitHub Actions install and committed; CI now uses `--frozen-lockfile` to prevent dependency drift. Avoid privileged or unreviewed contribution workflows.

There is **no backend, identity, global coin balance, public publishing, or MCP connector yet**. No game is currently playable in the platform.


## P1 playable prototype

`pnpm dev` or `pnpm build` now builds the vetted Tiny Catcher cartridge into `apps/web/public/cartridges/` before launching/exporting Next.js. Visit `/play` to use the original virtual handheld with touch, keyboard, Console/Game and browser fullscreen. The shell appearance and hardware budgets remain provisional. 

The current browser sandbox has been probed on local headless Chromium for denied fetch, missing Worker DOM, invalid pixels and infinite-loop termination. See [P1 security spike](p1-runtime-security.md). **Do not enable public game uploads** until the remaining cross-browser/mobile security gates in issue #4 have been satisfied.


## P2 curated catalog

`pnpm cartridge:build` builds *every* approved game from `packages/catalog/src/index.ts` into `apps/web/public/cartridges`; `pnpm cartridge:verify` checks byte-identical output and rejects unlisted extra `.slop` files. `pnpm build` includes these cartridges in the static export and generates `/library`, `/play`, and each curated `/play/[game]` route. See [Creator quickstart](creator-quickstart.md) for manual AI/human authoring. Public uploads, coins, PWA offline capability, and achievement awards are *not* implemented by this catalog milestone.


## Offline PWA + local save baseline

`pnpm build` produces the complete Next static export and then generates an immutable-revision Service Worker (`apps/web/out/sw.js`) from the actual exported HTML, JS, CSS, icon and approved cartridge files. Installation precaches the three games. After visiting a deployed HTTPS build and allowing installation, the game routes can be opened without network; test offline browser navigation separately on Chrome/Firefox/Android before claiming device compatibility. Each change creates a new cache revision; only Slopboy caches are deleted. Never cache private API endpoints or account tokens.

The Game SDK now exposes `context.storage.load()`, `save(value)`, and `erase()` to cartridges. The host owns IndexedDB, isolates slots by hardware ID/version and approved game ID, and rejects data over the current hardware `saveBytes` budget (8 KiB). Saves are *local, best-effort*, can be cleared by browser data settings, and are never authoritative for Slop Coins or public achievements. Circuit Slide is the initial restore/resume fixture. User account sync, export and full mobile/browser acceptance remain open.

PWA PNG icons are generated deterministically by `pnpm icons:build` (also run by `pnpm dev` and `pnpm build`). The source does not commit binary icon artifacts.
