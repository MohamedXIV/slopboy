# Account-local save isolation (managed QA)

When the managed flag is enabled, the canonical player resolves the verified QA account before mounting, with a five-second timeout and guest fallback. Account-specific local key prefix isolates both named and legacy local save records, including atomic writes and legacy copy operations. No guest data is moved or deleted. With the flag off the old local path remains unchanged. Offline page reopen without a verified account opens guest saves; account-specific offline resume is a separate UX problem. A running player stays attached to its initial local lane; reopening resolves the account again. Managed worker never rediscovers/rebinds to another account during play. Both managed and explicit backup requests from a scoped player bind the expected account, checked against the server session. Guest fallback with managed flag on does not offer cloud actions.

Existing guest progress is intentionally not imported automatically. A future explicit copy workflow and same-account offline resume should be added before public rollout. Account-local separation is application-level, not protection against a person with full browser/device access. No production configuration or privileges changed.
