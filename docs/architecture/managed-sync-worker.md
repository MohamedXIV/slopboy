# Managed autosave sync cycle

A host-invoked foreground cycle is implemented but not scheduled or enabled in the player yet. It checks active account scope, local opt-in generation and online state, claims a durable 120-second per-scope throttle across tabs, and either retries the exact pending envelope or exports the latest committed autosave by atomic insertion order. The first new autosave upgrades old records; old v1 records are not selected automatically. It coalesces rapid saves rather than promising every local autosave will reach the cloud. A new candidate is compared against the managed listing before staging. No requests are made offline or with consent off; every request carries the expected-account and device headers, and the server checks the actual account. An exact listing acknowledgment is required before clearing pending bytes. Ambiguous responses, quota, rate limits, retirement and cancellation retain pending bytes, not optimistic success.

The server's shared daily budget is the final bound, not the client timer. Scheduling and account discovery, manual-save auto backup, cross-device discovery/restore UI, retirement cleanup and hosted acceptance are still separate. No new runtime grants, automatic transfers or deletion in this slice.

Player integration: the canonical play page passes only the deployment feature flag, not session data. A private no-store account discovery endpoint returns a verified administrator account ID; the player uses an atomic IndexedDB browser ID and explicit confirmation before enabling. While the player remains mounted, foreground cycles run on the bounded timer, visibility and reconnect events. Opt-out aborts the active cycle and fences the generation. No new grants or feature flag activation; the control stays hidden when disabled. Manual sync, cross-device discovery, storage reclamation and hosted signed-in acceptance are still separate.
