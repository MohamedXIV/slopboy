# Managed autosave retention foundation (#36)

Migration 012 introduces an owner-only managed autosave lane, independent of pinned explicit cloud backups. Five ready entries are retained per account/game/browser installation (the currently supported hardware profile is fixed). Different installations do not silently evict one another. This intentionally refines the prior per-profile idea to protect different devices' progress. Shared 10 MiB account quota counts legacy, explicit and managed rows, including pending and logically retired bytes. At most 100 managed records per account until a verified reconciler releases them; this is a metadata safety ceiling, not a hardware restriction.

One pending reservation per installation, exact digest retry after the existing 60-second cooldown, immutable object keys, account lock shared with existing lanes. Confirmation is a trusted server action after verified object upload/readback. Only after confirmation, the oldest managed ready entry is logically retired by server insertion order. No bytes or records are deleted. Retired entries cannot be resurrected by a retry. Existing pinned backups remain separate and visible. The old APIs do not list or resolve managed objects.

**Not enabled:** no application EXECUTE grants, no network endpoint, worker, deletion, or quota reclamation. The existing operator inventory does not yet include this lane; extend audit and implement writer fencing/provider-verified retirement before activating any managed upload. Keep the production lane empty until those gates pass. Rollback refuses any managed records, even retired. Production migration may be applied after tests and owner approval, but does not enable sync.
