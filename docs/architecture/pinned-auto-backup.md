# Automatic pinned backup (QA only)

Independent opt-in for protected manual saves and local named backups, using the existing named immutable cloud endpoint. The managed autosave lane and its rolling five stay separate. Each lane has its own durable consent, pending envelope and 120-second throttle. Existing reviewed game capabilities control which records can be backed up; the currently reviewed save-enabled Circuit Slide supports autosaves and named local backups, not manual capture. The worker selects oldest eligible unbacked protected save, retries the exact pending bytes and requires an exact server acknowledgment. Renaming an already backed-up snapshot does not consume an additional cloud slot. A manual replacement is a new snapshot. No automatic propagation of local deletion or overwrite to existing cloud copies; pending exact bytes may still be retried after a local deletion. Cloud backups have the existing five named copies per game and shared 10 MiB cap. No eviction of protected copies. When full, sync reports quota and local saving continues; explicit cloud deletion/replacement UI is a follow-up. Account-bound read and write, no new runtime grants or production activation. Both lanes share the server request budget; foreground timers can hit that budget and must tolerate 429. No scheduled background service.
