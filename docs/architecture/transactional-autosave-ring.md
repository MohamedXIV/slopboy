# Transactional autosave ring (prelaunch proposal)

Managed autosaves are small and high churn. An external object delete cannot be safely coordinated with delayed PUT merely by adding a SQL status or client timeout. This alternative stores only canonical managed autosaves in PostgreSQL, retaining the existing named/legacy object-storage path unchanged. It avoids the distributed delete race entirely for new managed data: verify the exact envelope on the server, verify byte count and SHA-256 inside SQL, then insert and rotate the oldest of five in one account-serialized transaction. A failed transaction cannot remove a previous save. Readback verifies bytes and digest again. Existing object-backed managed records are preserved, separately audited and cannot mix with a transactional device stream.

Prelaunch hard ceilings: 256 KiB per envelope, existing 10 MiB shared account quota, 100 managed rows/account, 16 MiB and 1000 transactional rows globally. These are design limits, not Neon plan guarantees. PostgreSQL MVCC/WAL/backup overhead and vacuum must be monitored; logical payload cap does not bound physical DB size exactly. This intentionally trades storage scalability for transactional correctness; reconsider before public rollout. No infrastructure added. Existing 012/013 functions remain owner-only and must not be granted; grant only list/store_atomic/read_atomic to the reviewed server role once accepted. Migration 014 does not delete old data and rollback refuses existing transactional saves. The feature flag remains off. Existing manual backups remain pinned and unaffected. The inventory reports SQL-managed bytes separately from object inventory, with no raw data.

Scope: this is a prelaunch alternative for managed autosaves only, not automatic manual-save backup or public activation. Hosted tests and cross-device discovery/restore UI remain outstanding. Existing local saves are browser-scoped rather than account-owned; before enabling recurring uploads across sessions, ensure consent cannot accidentally transfer another account's progress.
