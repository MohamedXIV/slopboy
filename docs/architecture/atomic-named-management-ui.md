# Atomic named cloud management UI

When managed QA is enabled, named API uses the new restricted SQL store/read/delete functions. Every atomic request binds the expected account. Legacy object reads fall back to existing verified download, never deletion or replacement. DELETE requires exact backupId and digest; POST replacement uses the same target query and canonical new envelope. Origin, role, game and request budget are checked before mutation. Client checks returned tombstone and exact replacement acknowledgment, and never modifies local saves. Protected auto-sync skips deleted snapshot IDs and discards only the exact pending envelope on authenticated BACKUP_DELETED. No production grants or flag change yet. Older deployments' named reserve/confirm grants must be removed before activation so old writes cannot bypass tombstones. Existing object rows cannot be managed by new deletion functions. A deleted local snapshot must be backed up as a distinct new snapshot to upload again.
